# GuardianHub UAT Dataset & Reset Guide

## Purpose
Provides two isolated security-company tenants with realistic staging records for
role-based UAT and the Phase 15 release test suites. Staging only — never run the
seed against production.

## What the seed creates
- `UAT — Sentinel Security Ltd` (tenant A) — 2 clients, 3 sites, 4 guards
- `UAT — Apex Guarding Group` (tenant B) — 2 clients, 3 sites, 4 guards

Run: `supabase/seed/003_uat_dataset.sql`

## Reset
Run the reset block at the bottom of `003_uat_dataset.sql`, or manually delete by
the `UAT —` / `@*-uat.example` markers. The seed is idempotent (guarded by
`WHERE NOT EXISTS`), so re-running after reset restores the known state.

## What is intentionally NOT seeded
- Auth identities (FK to `auth.users`) — created via Auth admin.
- Stripe payment details / live credentials — never seeded.
- Shifts, incidents, SOS, timesheets, invoices, contracts, training, compliance
  and automation records — these are generated by exercising the app during the
  UAT journeys (Journeys A–G), which is the correct way to produce genuine test
  evidence rather than fabricated data.
